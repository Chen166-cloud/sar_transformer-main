# 真实 SAR 示例图画质检查

检查日期：2026-09-07。对象：本项目本地 Mendeley `fs455tz88y.1` Noisy 派生数据和已导出示例图。用户反馈来自项目示例图或论文图。

## 结论

常用城市纹理示例的细节限制主要已经存在于输入 MAT 中。该示例的 Noisy PNG 与原数组按标准 8 位灰度转换的结果逐像素一致，拼图未进一步缩放该图块。提高保存 DPI 或放大图片不会增加真实细节。

本地数据能正常读取，但具有明显离散灰度及开方型数值结构。尚未取得原发布 Noisy 文件逐像素对照，也未在项目中找到导入转换代码，因此不能把本地信息限制直接归因于数据集作者，或认定下载文件损坏。

## 需要追溯的数值域问题

5,626 张满足本次保守检测的开方离散格点：存在整数 N，使每个灰度 u 的 `N*u²` 在 float32 误差内接近整数。检测要求图中出现 0、1，且由第一个非零灰度推断 N；未通过或未进入检测的图不代表不存在类似结构。

例如 `train/0_10240_y0_x0.mat` 只有 44 个灰度，近似 `sqrt(k/43)`；城市纹理示例的 213 个灰度近似 `sqrt(k/212)`。独立跨三个物理目录抽查 12 张，包括未达到 1 的图，也观察到开方离散格点。

这一结构强烈提示早期存在离散化、缩放和开方型变换，但不能单凭数值确定原始物理单位、处理顺序或处理责任方。当前正式协议称输入为 intensity，实际源数据是否为强度、幅度或显示变换后的量，应重新核对来源。不要在缺少依据时直接平方或再次开方“修复”。

仓库及最早历史版本未找到真实 SAR 发布源图转当前 MAT 的完整转换流程。`resplit_real_sar_dataset.py` 仅生成分组清单，不处理像素。

- `prepare_icsps2026_real.py:127`、`:169`：正式流程使用全数据统一线性映射；[0,1] 输入保持原值，无 resize 或平滑，但此步骤不证明输入的物理数值域。

## 实际处理建议

1. 展示时明确标注 256×256 原始尺寸，采用原尺寸概览和标明倍率的局部图。放大只能改变显示大小。
2. 论文面板明确设置插值方式；检查像素细节时使用 nearest，避免阅读器自动平滑造成“更糊”的观感。同组方法采用相同显示范围。
3. 优先使用保存的浮点数组或已有正式 16 位导出，避免重复转换；这些做法只能减少新增损失。
4. 更关键的是取得同名原始 Noisy 样本，逐像素复核其位深、数值范围、开方、归一化和裁剪步骤，再确定是否需要重建数据或修正 intensity/幅度描述。此项上游追溯尚未完成。

本次没有修改数据、模型、训练配置、正式评价或论文图。只生成诊断材料。
